# MealSwap — Full-stack MVP

MealSwap is a student-to-student meal transfer website. A student lists an unused meal, another student books it, and the buyer receives a unique QR pass. Mess staff scan or paste the token to redeem it once.

## What is included

- Student registration and login
- Password hashing with bcrypt
- SQLite database (data stays on the server)
- List unused breakfast, lunch, snacks or dinner
- Browse available meals and book one
- Unique QR pass generated by the server
- Student booking history
- Mess staff account and protected redemption page
- One-time redemption: the same QR cannot be used twice
- Responsive layout for mobile and desktop

## Requirements

Install **Node.js LTS** on your computer. Check installation in Command Prompt:

```bash
node -v
npm -v
```

## Run on Windows

1. Extract the `MealSwap_Full_Website.zip` file.
2. Open the extracted `MealSwap_Full_Website` folder in VS Code.
3. Open Terminal → New Terminal.
4. Run:

```bash
npm install
```

5. Copy `.env.example` and rename the copy to `.env`.
6. Change `SESSION_SECRET` in `.env` to a long random value.
7. Start the website:

```bash
npm start
```

8. Open this address in Chrome:

```text
http://localhost:3000
```

The SQLite database and session database are created automatically in the `data` folder.

## Create a mess staff account

For the local pilot, create a setup key in `.env`:

```text
ADMIN_SETUP_KEY=make-a-long-one-time-key
```

Restart the server. Send a POST request to `/api/setup-admin` with JSON body:

```json
{
  "setupKey": "your-one-time-key",
  "name": "Mess Staff",
  "email": "mess@example.com",
  "password": "change-this-password"
}
```

You can use the Thunder Client extension in VS Code or Postman. After creating the account, remove `ADMIN_SETUP_KEY` from `.env` and restart the server. Log in through the website with the mess staff email and password. The mess verification section will appear.

## Important before a real campus launch

This is a functional full-stack MVP, but a real deployment still needs campus approval and operational setup:

1. **Meal entitlement approval:** the mess must agree that a student's unused meal can be transferred. The current app records a student-to-student transfer; it does not connect to a college mess database or prove the seller's original meal entitlement.
2. **Payments:** the current flow is pay-at-counter / offline settlement. Online payments require a Razorpay account, server-side order creation, webhook verification and refund handling. Never put secret payment keys in browser JavaScript.
3. **Hosting and HTTPS:** deploy the Node app and persistent SQLite storage to a suitable host, or move the database to managed PostgreSQL. Set `NODE_ENV=production`, a strong `SESSION_SECRET`, HTTPS and backups.
4. **Production hardening:** add college email verification, rate limiting, CSRF protection, admin audit logs, privacy policy, terms, support process and monitoring. Use a production session store.
5. **Real identity:** mess staff should check the buyer's college ID and the transfer rules before redeeming the QR.

## How the project is organised

- `server.js` — API routes, login, booking and QR verification.
- `database.js` — database tables.
- `public/index.html` — website structure.
- `public/style.css` — design and responsive layout.
- `public/app.js` — browser interactions and API calls.

The code is intentionally split into small functions with comments so it is easier to learn and edit.
